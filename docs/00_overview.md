# 00. Overview

## Project Summary

Cluster는 사진, 위치, 일정, 얼굴 인식 데이터를 조합해 사용자의 만남 기록을 자동으로 구조화하는 AI-assisted relationship memory application이다.

사용자는 사람, 장소, 일정을 등록하고 사진을 업로드한다. 백엔드는 사진의 EXIF 정보와 얼굴 인식 결과를 분석해 "언제, 어디서, 누구와 만났는지"를 추론하고, 사용자의 확인을 거쳐 실제 활동 기록으로 저장한다.

## Portfolio Goal

이 프로젝트는 실제 사용자 유치나 상용 운영보다, LLM/Application Engineer 직무에서 요구되는 백엔드 설계 능력과 기획 능력을 보여주는 것을 목표로 한다.

Cluster를 통해 보여주려는 핵심 역량은 다음과 같다.

- 복잡한 도메인을 User, Person, Place, Schedule, ActivityLog, Photo로 모델링하는 능력
- 사진 업로드 이후 EXIF 분석, 위치 기반 그룹화, 일정 후보 매칭, 얼굴 인식 결과 병합까지 이어지는 백엔드 파이프라인 설계 능력
- 메인 백엔드와 AI 서버를 분리하고 HTTP 계약 기반으로 연동하는 능력
- 분석 단계와 확정 단계를 분리해 데이터 일관성을 관리하는 능력
- 면접에서 로컬로 재현 가능한 데모와 테스트 가능한 구조를 만드는 능력

## Background

Cluster는 먼저 개인 프로젝트로 구현된 뒤, 교수님의 제안으로 학회 발표/논문으로 확장되었고 이후 수상까지 이어진 프로젝트다. 즉, 논문을 위해 만든 프로젝트가 아니라, 이미 구현된 제품 아이디어와 결과물을 학술적으로 정리해 인정받은 사례다.

포트폴리오 버전에서는 3개월 전 완성한 기존 MVP를 그대로 보존하는 것이 아니라, 같은 문제 정의와 제품 방향을 유지하면서 현재의 성장한 기준에 맞춰 백엔드 설계, AI 파이프라인, 데이터 모델, API 계약, 테스트 구조를 다시 정리한다.

수상/발표 이력은 프로젝트의 배경과 신뢰도 보강 자료로 사용하되, 포트폴리오의 핵심 평가는 실제 백엔드 설계와 구현 완성도에 둔다.

## Rebuild Direction

이번 작업은 제품 문제를 바꾸는 피벗이라기보다, 같은 문제를 더 성숙한 방식으로 해결하기 위한 re-architecture에 가깝다.

기존 프로젝트의 핵심 문제와 결과는 유지한다. 사용자의 만남 기록을 사진, 위치, 일정, 얼굴 인식 데이터를 통해 구조화한다는 방향은 그대로 둔다. 다만 이를 구현하는 백엔드 로직, 책임 분리, 데이터 일관성 관리, 외부 AI 서버 연동 방식, 테스트 가능성은 현재 기준에 맞게 다시 설계한다.

## Core Problem

사람들은 만남의 기록을 사진, 캘린더, 지도, 연락처에 흩어진 형태로 남긴다. 시간이 지나면 특정 만남이 언제, 어디서, 누구와 있었는지 다시 정리하기 어렵다.

Cluster는 사진에 포함된 시간/위치 정보와 얼굴 인식 결과를 활용해 흩어진 생활 데이터를 사람, 장소, 일정, 활동 로그로 구조화한다.

## Core Demo Scenario

면접에서 보여줄 대표 시나리오는 "사진 업로드 기반 만남 기록 자동화"이다.

1. 사용자가 로그인한다.
2. 사람과 장소를 등록한다.
3. 특정 날짜의 일정을 생성한다.
4. 사용자가 EXIF 정보가 포함된 사진을 업로드한다.
5. 백엔드는 사진의 날짜와 위치를 추출한다.
6. 백엔드는 사진을 날짜와 위치 기준으로 그룹화한다.
7. 백엔드는 기존 일정과 장소 후보를 찾는다.
8. 백엔드는 AI 서버에 얼굴 인식과 인물 매칭을 요청한다.
9. 백엔드는 일정 후보, 장소 후보, 인물 후보를 합쳐 분석 결과를 반환한다.
10. 사용자가 결과를 확정한다.
11. ActivityLog가 생성되고 사람/장소/일정 상태가 갱신된다.
12. 사용자는 사람 상세, 장소 상세, 캘린더에서 연결된 기록을 확인한다.

## Backend Focus

Cluster의 백엔드는 단순 CRUD보다 다음 영역에 집중한다.

- 도메인 모델링
- API 계약 설계
- 사진 분석 파이프라인
- AI 서버 연동 경계
- 트랜잭션과 데이터 일관성
- 예외 처리와 fallback 정책
- 테스트 가능한 계층 구조
- 로컬 데모 재현성

## Non-Goals

- 실제 사용자 유치나 운영용 배포는 목표가 아니다.
- 대규모 트래픽 처리나 고가용성 인프라 구축은 목표가 아니다.
- 프론트엔드 리디자인은 핵심 목표가 아니다.
- 얼굴 인식 모델 자체를 연구하거나 개선하는 것이 목표가 아니다.
- 모바일 네이티브 앱 출시는 목표가 아니다.
